1. Analytical Functions
1.1 Introduction to Window Functions
Window functions perform calculations across a set of rows that are related to the current row, without collapsing the result set like GROUP BY does.

┌─────────────────────────────────────────────────────────────────┐
│              AGGREGATE vs WINDOW FUNCTIONS                       │
├────────────────────────────┬────────────────────────────────────┤
│      GROUP BY (Aggregate)  │        WINDOW FUNCTION             │
├────────────────────────────┼────────────────────────────────────┤
│ Collapses rows             │ Preserves all rows                 │
│ One row per group          │ Adds calculation to each row       │
│ Cannot see individual rows │ Can access surrounding rows        │
│ Simple totals/averages     │ Running totals, rankings, etc.     │
└────────────────────────────┴────────────────────────────────────┘
Basic Syntax
function_name(arguments) OVER (
    [PARTITION BY partition_expression]
    [ORDER BY sort_expression [ASC|DESC]]
    [window_frame_clause]
)

1.2 Ranking Functions: ROW_NUMBER, RANK, DENSE_RANK
ROW_NUMBER()
Assigns a unique sequential number to each row:

/*
 * REAL-WORLD SCENARIO: Find top 3 sales per region
 */
SELECT *
FROM (
    SELECT 
        region,
        salesperson,
        amount,
        ROW_NUMBER() OVER (
            PARTITION BY region 
            ORDER BY amount DESC
        ) AS rank_in_region
    FROM sales_data
)
WHERE rank_in_region <= 3;

/*
Result:

North   Bob          1200    3
South   Carol        3600    1
South   David        2400    2
South   David        300     3
*/
RANK() vs DENSE_RANK()
/*
 * RANK: Leaves gaps after ties
 * DENSE_RANK: No gaps after ties

SELECT 
    salesperson,
    amount,
    RANK() OVER (ORDER BY amount DESC) AS rank_with_gaps,
    DENSE_RANK() OVER (ORDER BY amount DESC) AS rank_no_gaps,
    ROW_NUMBER() OVER (ORDER BY amount DESC) AS unique_number
FROM sales_data;

1.3 Aggregate Window Functions
Apply aggregate functions while keeping all rows:

/*
 * FINANCIAL REPORTING: Compare each sale to averages
 */
SELECT 
    sale_date,
    region,
    salesperson,
    amount,
    -- Total for entire dataset
    SUM(amount) OVER () AS grand_total,
    -- Total for this region
    SUM(amount) OVER (PARTITION BY region) AS region_total,
    -- Average for this salesperson
    ROUND(AVG(amount) OVER (PARTITION BY salesperson), 2) AS person_avg,
    -- Count of sales for this region
    COUNT(*) OVER (PARTITION BY region) AS region_sales_count,
    -- Percentage of region total
    ROUND(amount / SUM(amount) OVER (PARTITION BY region) * 100, 1) AS pct_of_region
FROM sales_data
ORDER BY region, sale_date;

1.4 LAG and LEAD Functions
Access data from previous or following rows:

/*
 * TREND ANALYSIS: Compare each sale to previous sale
 */
SELECT 
    sale_date,
    salesperson,
    amount,
    LAG(amount, 1, 0) OVER (ORDER BY sale_date) AS prev_sale,
    LEAD(amount, 1, 0) OVER (ORDER BY sale_date) AS next_sale,
    amount - LAG(amount, 1, 0) OVER (ORDER BY sale_date) AS change_from_prev
FROM sales_data
ORDER BY sale_date;

Real-World Example: Month-over-Month Growth
/*
 * BUSINESS INTELLIGENCE: Calculate MoM growth rate
 */
WITH monthly_sales AS (
    SELECT 
        TRUNC(sale_date, 'MM') AS month,
        SUM(amount) AS monthly_total
    FROM sales_data
    GROUP BY TRUNC(sale_date, 'MM')
)
SELECT 
    month,
    monthly_total,
    LAG(monthly_total) OVER (ORDER BY month) AS prev_month,
    ROUND(
        (monthly_total - LAG(monthly_total) OVER (ORDER BY month)) 
        / NULLIF(LAG(monthly_total) OVER (ORDER BY month), 0) * 100, 
        1
    ) AS growth_pct
FROM monthly_sales
ORDER BY month;

/*
Result:
MONTH       MONTHLY_TOTAL  PREV_MONTH  GROWTH_PCT
----------  -------------  ----------  ----------
2024-01-01  14250          NULL        NULL
2024-02-01  18500          14250       29.8
2024-03-01  16200          18500       -12.4
...
*/
Per-Salesperson Trend Analysis
/*
 * SALES MANAGEMENT: Track each salesperson's performance trend
 */
SELECT 
    salesperson,
    sale_date,
    amount,
    LAG(amount) OVER (
        PARTITION BY salesperson 
        ORDER BY sale_date
    ) AS prev_sale_by_person,
    CASE 
        WHEN amount > LAG(amount) OVER (PARTITION BY salesperson ORDER BY sale_date)
        THEN '↑ Improved'
        WHEN amount < LAG(amount) OVER (PARTITION BY salesperson ORDER BY sale_date)
        THEN '↓ Declined'
        WHEN LAG(amount) OVER (PARTITION BY salesperson ORDER BY sale_date) IS NULL
        THEN '● First Sale'
        ELSE '→ Same'
    END AS trend
FROM sales_data
ORDER BY salesperson, sale_date;
1.5 FIRST_VALUE, LAST_VALUE, NTH_VALUE
/*
 * COMPARISON ANALYSIS: Compare each sale to best/worst in region
 */
SELECT 
    region,
    salesperson,
    sale_date,
    amount,
    FIRST_VALUE(amount) OVER (
        PARTITION BY region 
        ORDER BY amount DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS highest_in_region,
    LAST_VALUE(amount) OVER (
        PARTITION BY region 
        ORDER BY amount DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS lowest_in_region,
    NTH_VALUE(amount, 2) OVER (
        PARTITION BY region 
        ORDER BY amount DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_highest
FROM sales_data
ORDER BY region, amount DESC;
⚠️ Important: LAST_VALUE and NTH_VALUE require explicit window frame specification to work correctly. Without it, the default frame
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
will give unexpected results.

1.6 Window Frame Specifications
Understanding ROWS vs RANGE
┌─────────────────────────────────────────────────────────────────┐
│                    WINDOW FRAMES                                 │
├────────────────────────────┬────────────────────────────────────┤
│           ROWS             │            RANGE                    │
├────────────────────────────┼────────────────────────────────────┤
│ Physical rows              │ Logical value range                │
│ Exact row count            │ All rows with same ORDER BY value  │
│ ROWS BETWEEN 2 PRECEDING   │ RANGE BETWEEN 100 PRECEDING        │
│   AND CURRENT ROW          │   AND CURRENT ROW                  │
│ Good for: moving averages  │ Good for: value-based windows      │
└────────────────────────────┴────────────────────────────────────┘
Frame Boundary Options
Boundary	Description
UNBOUNDED PRECEDING
First row of partition
n PRECEDING
n rows/values before current
CURRENT ROW
Current row
n FOLLOWING
n rows/values after current
UNBOUNDED FOLLOWING
Last row of partition
Moving Averages
/*
 * STOCK ANALYSIS: 3-day and 7-day moving averages
 */
WITH daily_sales AS (
    SELECT 
        sale_date,
        SUM(amount) AS daily_total
    FROM sales_data
    GROUP BY sale_date
)
SELECT 
    sale_date,
    daily_total,
    -- 3-day moving average (current + 2 preceding)
    ROUND(
        AVG(daily_total) OVER (
            ORDER BY sale_date
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ), 2
    ) AS moving_avg_3day,
    -- 7-day moving average
    ROUND(
        AVG(daily_total) OVER (
            ORDER BY sale_date
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ), 2
    ) AS moving_avg_7day,
    -- Centered 5-day average (2 before, current, 2 after)
    ROUND(
        AVG(daily_total) OVER (
            ORDER BY sale_date
            ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING
        ), 2
    ) AS centered_avg_5day
FROM daily_sales
ORDER BY sale_date;
Real-World Example: Rolling 12-Month Sales
/*
 * FINANCIAL REPORTING: Rolling 12-month sales analysis
 */
WITH monthly_revenue AS (
    SELECT 
        TRUNC(sale_date, 'MM') AS month,
        SUM(amount) AS revenue
    FROM sales_data
    GROUP BY TRUNC(sale_date, 'MM')
)
SELECT 
    month,
    revenue AS current_month,
    SUM(revenue) OVER (
        ORDER BY month
        ROWS BETWEEN 11 PRECEDING AND CURRENT ROW
    ) AS rolling_12_month,
    ROUND(
        AVG(revenue) OVER (
            ORDER BY month
            ROWS BETWEEN 11 PRECEDING AND CURRENT ROW
        ), 2
    ) AS avg_monthly_12m,
    -- YoY comparison
    LAG(revenue, 12) OVER (ORDER BY month) AS same_month_last_year,
    ROUND(
        (revenue - LAG(revenue, 12) OVER (ORDER BY month)) 
        / NULLIF(LAG(revenue, 12) OVER (ORDER BY month), 0) * 100,
        1
    ) AS yoy_growth_pct
FROM monthly_revenue
ORDER BY month;

2.2 CONNECT BY Clause
Basic Hierarchical Query
/*
 * ORGANIZATIONAL CHART: Display reporting structure
 */
SELECT 
    LEVEL,
    LPAD(' ', (LEVEL - 1) * 4) || employee_name AS org_chart,
    job_title,
    salary
FROM employees_hier
START WITH manager_id IS NULL          -- Start from CEO (no manager)
CONNECT BY PRIOR employee_id = manager_id  -- Parent-child relationship
ORDER SIBLINGS BY employee_name;       -- Order within same level

2.5 Additional Hierarchical Features
CONNECT_BY_ISLEAF and CONNECT_BY_ISCYCLE
/*
 * LEAF NODES: Find employees with no direct reports
 */
SELECT 
    employee_name,
    job_title,
    CONNECT_BY_ISLEAF AS is_leaf,
    CASE CONNECT_BY_ISLEAF 
        WHEN 1 THEN 'Individual Contributor'
        ELSE 'Manager'
    END AS role_type
FROM employees_hier
START WITH manager_id IS NULL
CONNECT BY PRIOR employee_id = manager_id;

-- Find only leaf nodes (no subordinates)
SELECT employee_name, job_title
FROM employees_hier
WHERE CONNECT_BY_ISLEAF = 1
START WITH manager_id IS NULL
CONNECT BY PRIOR employee_id = manager_id;

2.6 Recursive CTEs (WITH RECURSIVE)
Modern alternative to CONNECT BY (more portable):

/*
 * RECURSIVE CTE: Same org chart using WITH clause
 * (Oracle 11g R2+)
 */
WITH org_hierarchy (employee_id, employee_name, job_title, manager_id, lvl, path) AS (
    -- Anchor: Start with root nodes
    SELECT 
        employee_id, 
        employee_name, 
        job_title, 
        manager_id,
        1 AS lvl,
        employee_name AS path
    FROM employees_hier
    WHERE manager_id IS NULL
    
    UNION ALL
    
    -- Recursive: Join children to parents
    SELECT 
        e.employee_id,
        e.employee_name,
        e.job_title,
        e.manager_id,
        h.lvl + 1,
        h.path || ' → ' || e.employee_name
    FROM employees_hier e
    INNER JOIN org_hierarchy h ON e.manager_id = h.employee_id
)
SELECT 
    lvl AS level,
    LPAD(' ', (lvl - 1) * 4) || employee_name AS org_chart,
    job_title,
    path
FROM org_hierarchy
ORDER BY path;

/*
Result: Same as CONNECT BY but more portable to other databases

SELECT * FROM dual;

-- Calculate total cost of product
WITH bom_exploded AS (
    SELECT 
        component_id,
        component_name,
        quantity,
        unit_cost,
        quantity * unit_cost AS line_cost,
        1 AS multiplier,
        LEVEL AS lvl
    FROM bom
    START WITH parent_id IS NULL
    CONNECT BY PRIOR component_id = parent_id
)
SELECT 
    LPAD(' ', (lvl - 1) * 2) || component_name AS component,
    quantity,
    unit_cost,
    line_cost
FROM bom_exploded;

3.1 Correlated Subqueries
A correlated subquery references columns from the outer query and executes once per outer row:

/*
 * SCENARIO: Find employees earning more than their department average
 */
SELECT 
    e.employee_name,
    e.department,
    e.salary,
    (SELECT AVG(salary) FROM employees_hier 
     WHERE department = e.department) AS dept_avg
FROM employees_hier e
WHERE e.salary > (
    SELECT AVG(salary)
    FROM employees_hier
    WHERE department = e.department  -- Correlated!
);

3.3 Inline Views (Subqueries in FROM)
/*
 * ANALYTICS: Calculate statistics and join back
 */
SELECT 
    e.employee_name,
    e.salary,
    e.department,
    dept_stats.avg_salary,
    dept_stats.min_salary,
    dept_stats.max_salary,
    dept_stats.emp_count,
    ROUND((e.salary - dept_stats.avg_salary) / dept_stats.avg_salary * 100, 1) AS pct_above_avg
FROM employees_hier e
JOIN (
    -- Inline view calculating department statistics
    SELECT 
        department,
        AVG(salary) AS avg_salary,
        MIN(salary) AS min_salary,
        MAX(salary) AS max_salary,
        COUNT(*) AS emp_count
    FROM employees_hier
    GROUP BY department
) dept_stats ON e.department = dept_stats.department
ORDER BY e.department, e.salary DESC;
3.4 EXISTS vs IN
Performance Comparison
/*
 * EXISTS: Stops at first match (short-circuits)
 * IN: Evaluates all values in subquery
 */

-- Use EXISTS when subquery returns many rows
-- Finds customers who have placed orders
SELECT c.customer_id, c.customer_name
FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o 
    WHERE o.customer_id = c.customer_id
);

-- Use IN when subquery returns few distinct values
-- Finds customers in specific regions
SELECT customer_id, customer_name
FROM customers
WHERE region_id IN (SELECT region_id FROM regions WHERE country = 'USA');
NOT EXISTS vs NOT IN
/*
 * CRITICAL DIFFERENCE: NULL handling!
 * NOT IN fails if subquery contains NULL
 * NOT EXISTS handles NULLs correctly
 */

-- Find customers with no orders
-- SAFE: Use NOT EXISTS
SELECT c.customer_id, c.customer_name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o 
    WHERE o.customer_id = c.customer_id
);

-- DANGEROUS: NOT IN with potential NULLs
-- If orders.customer_id contains any NULL, this returns NO ROWS!
SELECT customer_id, customer_name
FROM customers
WHERE customer_id NOT IN (SELECT customer_id FROM orders);
-- Fix: Add NULL filter
WHERE customer_id NOT IN (SELECT customer_id FROM orders WHERE customer_id IS NOT NULL);

Basic CTE
/*
 * CTE: Named subquery for better readability and reuse
 */
WITH 
    dept_stats AS (
        SELECT 
            department,
            AVG(salary) AS avg_salary,
            SUM(salary) AS total_salary,
            COUNT(*) AS emp_count
        FROM employees_hier
        GROUP BY department
    ),
    company_stats AS (
        SELECT 
            AVG(salary) AS company_avg,
            SUM(salary) AS company_total
        FROM employees_hier
    )
SELECT 
    d.department,
    d.emp_count,
    ROUND(d.avg_salary, 2) AS dept_avg,
    d.total_salary,
    ROUND(d.total_salary / c.company_total * 100, 1) AS pct_of_total,
    CASE 
        WHEN d.avg_salary > c.company_avg THEN 'Above Average'
        ELSE 'Below Average'
    END AS status
FROM dept_stats d
CROSS JOIN company_stats c
ORDER BY d.total_salary DESC;
Multiple CTEs with Dependencies
/*
 * SALES ANALYSIS: Multi-level aggregation
 */
WITH 
    -- Level 1: Daily sales by salesperson
    daily_sales AS (
        SELECT 
            salesperson,
            TRUNC(sale_date) AS sale_date,
            SUM(amount) AS daily_total
        FROM sales_data
        GROUP BY salesperson, TRUNC(sale_date)
    ),
    -- Level 2: Monthly summary (references daily_sales)
    monthly_sales AS (
        SELECT 
            salesperson,
            TRUNC(sale_date, 'MM') AS month,
            SUM(daily_total) AS monthly_total,
            COUNT(DISTINCT sale_date) AS active_days,
            AVG(daily_total) AS avg_daily
        FROM daily_sales
        GROUP BY salesperson, TRUNC(sale_date, 'MM')
    ),
    -- Level 3: Rankings (references monthly_sales)
    ranked_sales AS (
        SELECT 
            salesperson,
            month,
            monthly_total,
            active_days,
            avg_daily,
            RANK() OVER (PARTITION BY month ORDER BY monthly_total DESC) AS monthly_rank
        FROM monthly_sales
    )
SELECT *
FROM ranked_sales
WHERE monthly_rank <= 3
ORDER BY month, monthly_rank;
CTE for Data Transformation
/*
 * DATA CLEANING: Use CTE to stage transformations
 */
WITH 
    cleaned_data AS (
        SELECT 
            UPPER(TRIM(customer_name)) AS customer_name,
            REGEXP_REPLACE(phone, '[^0-9]', '') AS phone_cleaned,
            LOWER(TRIM(email)) AS email,
            COALESCE(status, 'ACTIVE') AS status
        FROM raw_customers
        WHERE customer_name IS NOT NULL
    ),
    deduplicated AS (
        SELECT 
            customer_name,
            phone_cleaned,
            email,
            status,
            ROW_NUMBER() OVER (
                PARTITION BY email 
                ORDER BY customer_name
            ) AS dup_num
        FROM cleaned_data
    )
SELECT customer_name, phone_cleaned, email, status
FROM deduplicated
WHERE dup_num = 1;

MERGE combines INSERT and UPDATE in a single statement:

/*
 * REAL-WORLD SCENARIO: Sync inventory from supplier feed
 */

-- Source: Daily supplier inventory file
CREATE TABLE supplier_inventory (
    product_code    VARCHAR2(20),
    product_name    VARCHAR2(100),
    quantity        NUMBER,
    unit_price      NUMBER(10,2),
    last_updated    DATE
);

-- Target: Our inventory table
CREATE TABLE warehouse_inventory (
    product_code    VARCHAR2(20) PRIMARY KEY,
    product_name    VARCHAR2(100),
    quantity        NUMBER,
    unit_price      NUMBER(10,2),
    last_updated    DATE,
    created_date    DATE
);

-- MERGE: Insert new products, update existing ones
MERGE INTO warehouse_inventory tgt
USING supplier_inventory src
ON (tgt.product_code = src.product_code)

-- When product exists: Update
WHEN MATCHED THEN
    UPDATE SET
        tgt.product_name = src.product_name,
        tgt.quantity = src.quantity,
        tgt.unit_price = src.unit_price,
        tgt.last_updated = SYSDATE
    -- Optional: Delete if quantity is 0
    DELETE WHERE src.quantity = 0

-- When product is new: Insert
WHEN NOT MATCHED THEN
    INSERT (product_code, product_name, quantity, unit_price, last_updated, created_date)
    VALUES (src.product_code, src.product_name, src.quantity, src.unit_price, SYSDATE, SYSDATE);

-- Check results
SELECT * FROM warehouse_inventory;

    GROUPING(region) AS is_region_subtotal,

CUBE - All Dimension Combinations
/*
 * ANALYSIS: All possible subtotals
 */
SELECT 
    COALESCE(region, 'ALL REGIONS') AS region,
    COALESCE(product, 'ALL PRODUCTS') AS product,
    SUM(amount) AS total_sales,
    COUNT(*) AS num_sales
FROM sales_data
GROUP BY CUBE(region, product)
ORDER BY region, product;

/*
Result includes:
- Each region + each product
- Each region + ALL products (region subtotals)
- ALL regions + each product (product subtotals)
- ALL regions + ALL products (grand total)
*/

/*
 * CUSTOM SUBTOTALS: Only specific groupings
 */
SELECT 
    region,
    product,
    salesperson,
    SUM(amount) AS total_sales
FROM sales_data
GROUP BY GROUPING SETS (
    (region, product),           -- Sales by region and product
    (region, salesperson),       -- Sales by region and person
    (region),                    -- Region subtotals only
    ()                           -- Grand total
)
ORDER BY region NULLS LAST, product NULLS LAST, salesperson NULLS LAST;

        COALESCE(region, '** ALL **') AS region,
        COALESCE(TO_CHAR(sale_date, 'YYYY-MM'), '** ALL **') AS month,
        COALESCE(product, '** ALL **') AS product,
        SUM(amount) AS revenue,
        COUNT(*) AS transactions,
        SUM(quantity) AS units_sold
    FROM sales_data
    GROUP BY CUBE(region, TO_CHAR(sale_date, 'YYYY-MM'), product)
)
SELECT *
FROM sales_summary
WHERE 
    -- Show useful combinations only
    (region = '** ALL **' AND month != '** ALL **' AND product = '** ALL **')  -- Monthly totals
    OR (region != '** ALL **' AND month = '** ALL **' AND product = '** ALL **')  -- Regional totals
    OR (region = '** ALL **' AND month = '** ALL **' AND product != '** ALL **')  -- Product totals
    OR (region = '** ALL **' AND month = '** ALL **' AND product = '** ALL **')   -- Grand total
ORDER BY region, month, product;
5.4 GROUPING and GROUPING_ID
/*
 * IDENTIFY aggregation levels
 */
SELECT 
    region,
    salesperson,
    SUM(amount) AS total,
    CASE GROUPING_ID(region, salesperson)
        WHEN 0 THEN 'Detail'
        WHEN 1 THEN 'Region Subtotal'
        WHEN 3 THEN 'Grand Total'
    END AS row_type
FROM sales_data
GROUP BY ROLLUP(region, salesperson);

/*
GROUPING_ID returns a bitmap:
- 0 (binary 00): Both columns are regular values
- 1 (binary 01): salesperson is aggregated (NULL)
- 3 (binary 11): Both columns are aggregated (grand total)
*/
5.5 MODEL Clause (Spreadsheet Calculations)
/*
 * ADVANCED: Spreadsheet-like calculations
 * Calculate forecasts based on growth rate
 */
SELECT region, year, sales, forecast
FROM (
    SELECT region, EXTRACT(YEAR FROM sale_date) AS year, SUM(amount) AS sales
    FROM sales_data
    GROUP BY region, EXTRACT(YEAR FROM sale_date)
)
MODEL
    PARTITION BY (region)
    DIMENSION BY (year)
    MEASURES (sales, 0 AS forecast)
    RULES (
        -- Calculate 10% growth forecast for next year
        forecast[2025] = sales[2024] * 1.10,
        forecast[2026] = sales[2025] * 1.10
    )
ORDER BY region, year;

/*
Result:
REGION   YEAR   SALES    FORECAST
------   ----   ------   --------
North    2024   7700     0
North    2025   NULL     8470      <- Calculated: 7700 * 1.10
North    2026   NULL     9317      <- Calculated: 8470 * 1.10
South    2024   6550     0
South    2025   NULL     7205
South    2026   NULL     7925.5
*/

6.3 Analytics Queries
Query 1: Salesperson Performance Dashboard
/*
 * PERFORMANCE DASHBOARD: Rankings, comparisons, trends
 */
WITH salesperson_metrics AS (
    SELECT 
        salesperson_id,
        salesperson,
        region,
        SUM(amount) AS total_sales,
        COUNT(DISTINCT customer_id) AS unique_customers,
        COUNT(*) AS transaction_count,
        AVG(amount) AS avg_transaction,
        SUM(quantity) AS units_sold
    FROM sales_transactions
    WHERE EXTRACT(YEAR FROM txn_date) = 2024
    GROUP BY salesperson_id, salesperson, region
)
SELECT 
    salesperson,
    region,
    total_sales,
    unique_customers,
    transaction_count,
    ROUND(avg_transaction, 2) AS avg_transaction,
    -- Rankings
    RANK() OVER (ORDER BY total_sales DESC) AS company_rank,
    RANK() OVER (PARTITION BY region ORDER BY total_sales DESC) AS region_rank,
    -- Percentile
    ROUND(PERCENT_RANK() OVER (ORDER BY total_sales) * 100, 1) AS percentile,
    -- Comparison to average
    ROUND(total_sales / AVG(total_sales) OVER () * 100, 1) AS pct_of_avg,
    -- Share of region
    ROUND(total_sales / SUM(total_sales) OVER (PARTITION BY region) * 100, 1) AS region_share
FROM salesperson_metrics
ORDER BY total_sales DESC;
Query 2: Monthly Trend Analysis
/*
 * TREND ANALYSIS: MoM and YoY comparisons
 */
WITH monthly_data AS (
    SELECT 
        TRUNC(txn_date, 'MM') AS month,
        region,
        SUM(amount) AS revenue,
        COUNT(*) AS transactions,
        COUNT(DISTINCT customer_id) AS customers
    FROM sales_transactions
    GROUP BY TRUNC(txn_date, 'MM'), region
)
SELECT 
    month,
    region,
    revenue,
    transactions,
    customers,
    -- Previous month comparison
    LAG(revenue) OVER (PARTITION BY region ORDER BY month) AS prev_month_revenue,
    ROUND(
        (revenue - LAG(revenue) OVER (PARTITION BY region ORDER BY month)) 
        / NULLIF(LAG(revenue) OVER (PARTITION BY region ORDER BY month), 0) * 100, 
        1
    ) AS mom_growth_pct,
    -- Same month last year
    LAG(revenue, 12) OVER (PARTITION BY region ORDER BY month) AS same_month_ly,
    ROUND(
        (revenue - LAG(revenue, 12) OVER (PARTITION BY region ORDER BY month)) 
        / NULLIF(LAG(revenue, 12) OVER (PARTITION BY region ORDER BY month), 0) * 100, 
        1
    ) AS yoy_growth_pct,
    -- 3-month moving average
    ROUND(AVG(revenue) OVER (
        PARTITION BY region ORDER BY month
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ), 2) AS moving_avg_3m,
    -- Running total YTD
    SUM(revenue) OVER (
        PARTITION BY region, EXTRACT(YEAR FROM month)
        ORDER BY month
    ) AS ytd_revenue
FROM monthly_data
ORDER BY region, month;

Query 4: Hierarchical Territory Report
/*
 * HIERARCHY: Region > Territory > Salesperson
 */
WITH territory_summary AS (
    SELECT 
        region,
        territory,
        salesperson,
        SUM(amount) AS sales
    FROM sales_transactions
    GROUP BY region, territory, salesperson
)
SELECT 
    LPAD(' ', (LEVEL - 1) * 4) || 
    CASE LEVEL
        WHEN 1 THEN 'Region: ' || region
        WHEN 2 THEN 'Territory: ' || territory
        WHEN 3 THEN salesperson
    END AS hierarchy,
    sales
FROM (
    -- Aggregate at different levels
    SELECT region, NULL AS territory, NULL AS salesperson, SUM(sales) AS sales, 1 AS lvl
    FROM territory_summary GROUP BY region
    UNION ALL
    SELECT region, territory, NULL, SUM(sales), 2
    FROM territory_summary GROUP BY region, territory
    UNION ALL
    SELECT region, territory, salesperson, sales, 3
    FROM territory_summary
)
START WITH territory IS NULL AND salesperson IS NULL
CONNECT BY PRIOR region = region 
       AND (PRIOR territory IS NULL AND territory IS NOT NULL
            OR PRIOR territory = territory AND PRIOR salesperson IS NULL)
ORDER SIBLINGS BY sales DESC;
Query 5: Customer Segmentation with Analytics
/*
 * RFM ANALYSIS: Recency, Frequency, Monetary
 */
WITH customer_rfm AS (
    SELECT 
        customer_id,
        customer_name,
        MAX(txn_date) AS last_purchase,
        COUNT(*) AS frequency,
        SUM(amount) AS monetary,
        TRUNC(SYSDATE) - MAX(txn_date) AS recency_days
    FROM sales_transactions
    GROUP BY customer_id, customer_name
),
rfm_scores AS (
    SELECT 
        customer_id,
        customer_name,
        last_purchase,
        recency_days,
        frequency,
        monetary,
        -- Score 1-5 (5 is best)
        NTILE(5) OVER (ORDER BY recency_days DESC) AS r_score,
        NTILE(5) OVER (ORDER BY frequency) AS f_score,
        NTILE(5) OVER (ORDER BY monetary) AS m_score
    FROM customer_rfm
)
SELECT 
    customer_id,
    customer_name,
    recency_days,
    frequency,
    monetary,
    r_score, f_score, m_score,
    r_score || f_score || m_score AS rfm_segment,
    CASE 
        WHEN r_score >= 4 AND f_score >= 4 AND m_score >= 4 THEN 'Champions'
        WHEN r_score >= 4 AND f_score >= 3 THEN 'Loyal Customers'
        WHEN r_score >= 4 AND m_score >= 4 THEN 'Big Spenders'
        WHEN r_score <= 2 AND f_score >= 4 THEN 'At Risk'
        WHEN r_score <= 2 AND f_score <= 2 THEN 'Lost'
        ELSE 'Regular'
    END AS customer_segment
FROM rfm_scores
ORDER BY monetary DESC;

Lab Exercise 4: MERGE for Data Synchronization (30 min)
/*
 * LAB 4: Implement Data Synchronization
 * 
 * Scenario: Sync product prices from supplier feed
 * - Update prices for existing products
 * - Add new products
 * - Mark discontinued products as inactive
 */

-- Create source (supplier feed)
CREATE TABLE supplier_prices (
    product_code VARCHAR2(20),
    product_name VARCHAR2(100),
    new_price NUMBER(10,2),
    is_available CHAR(1)
);

-- Create target (our catalog)
CREATE TABLE product_catalog (
    product_code VARCHAR2(20) PRIMARY KEY,
    product_name VARCHAR2(100),
    current_price NUMBER(10,2),
    status VARCHAR2(20),
    last_updated DATE
);

-- Insert test data
INSERT INTO product_catalog VALUES ('P001', 'Old Laptop', 999, 'ACTIVE', SYSDATE-30);
INSERT INTO product_catalog VALUES ('P002', 'Old Mouse', 29, 'ACTIVE', SYSDATE-30);

INSERT INTO supplier_prices VALUES ('P001', 'New Laptop Pro', 1099, 'Y');
INSERT INTO supplier_prices VALUES ('P003', 'New Keyboard', 79, 'Y');
INSERT INTO supplier_prices VALUES ('P002', 'Mouse', 29, 'N');  -- Discontinued

-- MERGE solution
MERGE INTO product_catalog tgt
USING supplier_prices src
ON (tgt.product_code = src.product_code)

WHEN MATCHED THEN
    UPDATE SET
        tgt.product_name = src.product_name,
        tgt.current_price = src.new_price,
        tgt.status = CASE src.is_available WHEN 'Y' THEN 'ACTIVE' ELSE 'DISCONTINUED' END,
        tgt.last_updated = SYSDATE

WHEN NOT MATCHED THEN
    INSERT (product_code, product_name, current_price, status, last_updated)
    VALUES (src.product_code, src.product_name, src.new_price, 
            CASE src.is_available WHEN 'Y' THEN 'ACTIVE' ELSE 'DISCONTINUED' END,
            SYSDATE)
    WHERE src.is_available = 'Y';  -- Only insert available products

-- Verify
SELECT * FROM product_catalog ORDER BY product_code;
8. Module Summary
8.1 Key Concepts Review
Topic	Key Points
Window Functions	Perform calculations across related rows without collapsing results
ROW_NUMBER, RANK, DENSE_RANK	Different ranking behaviors for ties
LAG/LEAD	Access previous/next row values
Window Frames	ROWS vs RANGE, PRECEDING/FOLLOWING/UNBOUNDED
CONNECT BY	Oracle's traditional hierarchical query syntax
Recursive CTE	Modern, portable alternative to CONNECT BY
Correlated Subqueries	Reference outer query, execute per row
CTEs (WITH)	Named subqueries for readability and reuse
MERGE	UPSERT: combined INSERT/UPDATE/DELETE
Multi-table INSERT	Distribute rows to multiple tables
PIVOT/UNPIVOT	Transform rows↔columns
ROLLUP/CUBE	Hierarchical and multi-dimensional subtotals
8.2 Quick Reference
-- Window Function Syntax
function() OVER (
    PARTITION BY col
    ORDER BY col
    ROWS BETWEEN n PRECEDING AND m FOLLOWING
)

-- Hierarchical Query
SELECT ... FROM table
START WITH condition
CONNECT BY PRIOR parent = child
ORDER SIBLINGS BY col;

-- Recursive CTE
WITH cte (cols) AS (
    SELECT ... -- Anchor
    UNION ALL
    SELECT ... FROM cte JOIN table ON ... -- Recursive
)
SELECT * FROM cte;

-- MERGE
MERGE INTO target USING source ON (join_condition)
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT ...;

-- PIVOT
SELECT * FROM table
PIVOT (agg_function FOR column IN (values));

-- ROLLUP/CUBE
GROUP BY ROLLUP(col1, col2)  -- Hierarchical subtotals
GROUP BY CUBE(col1, col2)    -- All combinations
8.3 Performance Tips
Feature	Performance Consideration
Window Functions	Use appropriate window frame; avoid unnecessary PARTITION BY
Hierarchical Queries	Add NOCYCLE to prevent infinite loops; use LEVEL for filtering
Correlated Subqueries	Consider rewriting as JOINs or analytical functions
MERGE	Ensure join columns are indexed; use batch sizes for large data
PIVOT	Limit IN clause values; use subqueries for dynamic pivoting
